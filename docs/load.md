# 부하 테스트 리포트 (2026-11-04)

로드맵 43번. 의존성 없는 수집 서버(`server/index.js`, Node 한 프로세스) 하나가 SSE 구독자 1,000개를 든 채 초당 이벤트 500건을 10분간 받을 때의 지연·유실·메모리·CPU를 쟀고, 병목 두 가지를 고쳤다. **로컬 PC 기준**이라 절대값보다 "어디서 무너지는가"를 본다.

## 환경·방법

- PC: WSL2(Linux 6.18), 8 vCPU, 20GB. Node v22.9.0. 생성기와 서버가 **같은 PC**에서 돈다(생성기는 worker_threads 4개로 구독자를 나눠 들고, 메인 스레드가 이벤트를 넣는다).
- 도구: `tests/load/run.js`(의존성 0, k6 대신). 서버를 빈 포트에 띄우고(`EVENTS_PER_IP_MIN`·`SITE_EVENTS_PER_MIN`·`MAX_SSE_PER_SITE`는 풀어 둠) 구독자 S개가 전부 붙은 뒤 초당 E건을 D초 동안 20건 배치로 POST한다.
- 재는 것: **지연** = 이벤트 `timestamp` → 구독자 수신(ms, 표본 구독자 10개 × 모든 프레임, p50/p95/p99). **유실** = 구독자별 받은 `event` 프레임 수 ÷ 가장 많이 받은 구독자(스냅샷으로 떨어진 재접속 구독자는 그 구간이 유실로 잡힌다 — 상태는 맞지만 프레임은 안 왔으므로). **RSS·CPU** = `/healthz`의 rss와 `/proc/<pid>/stat`을 5초마다. **재접속** = `--reconnect 0.1`이면 30초마다 구독자 10%를 끊고 `Last-Event-ID`로 다시 붙여 `state.totals.sse`(복구 건수·resume 횟수·스냅샷 횟수)를 읽는다.
- 이벤트 믹스: `--heartbeat 0.66`(기본)은 SDK의 실제 비율에 가깝게 세션 시작 1 : 이동 1 : 하트비트 2. **하트비트는 세션 상태를 바꾸지 않아 SSE로 나가지 않는다**. 그래서 초당 500건을 받아도 팬아웃은 초당 약 150프레임이다. `--heartbeat 0`은 모든 이벤트가 이동(page_view)이라 팬아웃 최악 조건(초당 ≈410프레임 × 1,000 = 41만 write/초).
- 재현: `node tests/load/run.js --subs 1000 --rate 500 --secs 600 --reconnect 0.1` (마지막 줄 JSON, 그 위에 아래 표 한 줄).

## 고친 것

둘 다 `server/index.js`. 효과가 큰 것은 2번이다.

1. **스냅샷 프레임 캐시 + 링버퍼 이어 붙이기**(`SNAPSHOT_CACHE_MS`, 기본 1초): 같은 1초 안에 붙는 연결은 같은 스냅샷 문자열을 받고, 그 스냅샷 id 뒤에 생긴 프레임을 링버퍼에서 이어 받아 상태가 같아진다(44의 resume 경로 재사용). 발자국은 `TRAILS_CACHE_MS`(기본 60초) 캐시. 실제 믹스 60초 비교(1회씩): p50 15 → 9, p95 104 → 39, p99 124 → 65 ms.
2. **같은 틱의 프레임을 구독자당 write 한 번으로**: `broadcast()`가 프레임을 사이트별 문자열에 모았다가 `setImmediate`에 한 번에 쓴다. POST 배치 20건이면 write가 1/20. 새 구독자를 더하기 전에 flush해 스냅샷·resume과 순서가 어긋나지 않는다.

## 남은 한계와 다음

- Node 한 프로세스의 팬아웃 상한은 이 PC에서 **구독자 1,000 × 초당 1,500건 근처**(CPU 84%)다. 그 위는 46(수평 확장: 서버 2대, Postgres LISTEN/NOTIFY)으로 구독자를 나누는 것이 답이고, 그 전에 프레임 압축(세션 ID 짧게, 불필요한 속성 제거)으로 바이트를 줄일 수 있다.
- 링버퍼 크기는 "분당 6,000건 사이트의 10초"로 잡았다(`SSE_BUFFER`). 재접속이 그보다 오래 걸리면 스냅샷으로 돌아가며, 그 자체는 정상 동작이다.
- 생성기와 서버가 한 PC라 CPU를 나눠 쓴다. 생성기 부담은 구독자 수신 파싱(worker 4개)이고, 서버 CPU는 `/proc`으로 서버 프로세스만 잰 값이다.
- 이 리포트의 수치는 각 시나리오 1회 실행이다. 재현 명령은 위에 있다.
