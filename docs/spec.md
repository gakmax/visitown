# Visitown — 프로토타입 기능 명세서

**문서 버전:** v0.1  
**단계:** Prototype / PoC  
**제품 유형:** 실시간 웹사이트 방문자 시각화 서비스  
**핵심 콘셉트:** 싸이월드 미니홈피 × 2D 소셜 게임 × 웹 애널리틱스

---

## 1. 프로젝트 개요

### 1.1 서비스 정의

Visitown은 웹사이트의 방문자 행동 데이터를 귀여운 2D 가상 공간에 실시간으로 시각화하는 서비스다.

기존 웹 애널리틱스가 숫자, 차트, 표를 통해 사용자 행동을 설명했다면, Visitown은 방문자를 캐릭터로, 웹페이지를 건물이나 방으로 표현한다.

방문자의 유입·이동·체류·이탈을 게임 속 캐릭터의 행동으로 변환하여 웹사이트가 실제로 살아 움직이는 듯한 경험을 제공한다.

### 1.2 핵심 가치

- **시각적 직관성:** 방문자가 어느 페이지에 집중되는지 공간적으로 파악
- **감성적 재미:** 미니홈피와 픽셀 게임의 감성으로 방문자 관찰 자체를 재미있게 표현
- **실시간성:** 페이지 이동과 주요 이벤트를 지연을 최소화하여 반영
- **간편한 설치:** 기존 웹사이트에 최소한의 코드로 연동
- **공유 가능성:** 웹사이트의 활동 상황을 타인에게 보여줄 수 있는 독특한 화면 제공

### 1.3 핵심 사용자

1. 개인 웹사이트 및 사이드 프로젝트 개발자
2. 인디 해커 및 1인 SaaS 운영자
3. 스타트업 개발자 및 서비스 운영자
4. 웹사이트 제작사 및 에이전시

### 1.4 프로토타입 목표

실제 웹사이트에서 발생한 방문자 이벤트를 수집하고, 해당 정보를 캐릭터의 이동과 공간별 밀집도로 표현할 수 있는지 기술적·사용성 관점에서 검증한다.

**핵심 검증 질문**

> "기존 GA4 대시보드에서는 느끼기 어려운 재미와 직관성을 2D 가상 공간으로 제공할 수 있는가?"

## 2. 프로토타입 핵심 시나리오

### 시나리오 A — 신규 방문자 유입

1. 사용자가 추적 대상 웹사이트에 접속한다.
2. 이벤트 수집 SDK가 `session_start`와 `page_view`를 전송한다.
3. Visitown 서버가 방문자 세션을 생성한다.
4. 마을 입구에 랜덤 캐릭터가 등장한다.
5. 캐릭터가 현재 접속한 페이지에 대응하는 건물로 이동한다.
6. 해당 건물의 방문자 수가 증가한다.

### 시나리오 B — 페이지 이동

1. 방문자가 메인 페이지에서 상품 페이지로 이동한다.
2. SDK가 새 `page_view` 이벤트를 전송한다.
3. 서버에서 세션의 현재 페이지가 변경된다.
4. 캐릭터가 기존 건물에서 상품 페이지 건물로 이동한다.
5. 기존 건물의 인원은 감소하고 새 건물의 인원은 증가한다.

실제 웹페이지의 클릭 좌표나 마우스 움직임을 그대로 재현하는 것이 아니라, **페이지 이동 이벤트를 가상의 이동 애니메이션으로 표현한다.**

### 시나리오 C — 특정 페이지에 방문자 집중

1. 특정 상품 페이지에 방문자가 몰린다.
2. 해당 건물 주변에 캐릭터가 증가한다.
3. 건물 위에 현재 활성 방문자 수가 표시된다.
4. 밀집도에 따라 건물 주변 시각 효과가 달라진다.
5. 건물을 선택하면 페이지 경로와 현재 방문자 수를 확인할 수 있다.

### 시나리오 D — 방문자 이탈

1. 방문자가 웹사이트를 떠나거나 세션이 비활성화된다.
2. 서버가 해당 세션을 비활성 상태로 판단한다.
3. 캐릭터가 마을을 떠나는 애니메이션을 실행한다.
4. 활성 방문자 수가 감소한다.

브라우저 종료 시 이탈 이벤트가 항상 전달되는 것은 아니므로 Heartbeat 기반 만료 처리를 함께 사용한다.

### 시나리오 E — 커스텀 이벤트 발생

1. 방문자가 검색 버튼 또는 상품 구매 버튼을 클릭한다.
2. SDK가 커스텀 이벤트를 서버에 전달한다.
3. 해당 캐릭터 위에 말풍선이나 이펙트가 발생한다.
4. 이벤트 피드에 새로운 활동이 기록된다.

## 3. 기능 요구사항

### 3.1 기능 목록

| ID   | 기능                       | 우선순위 |
| ---- | -------------------------- | -------- |
| F-01 | 웹사이트 등록              | P0       |
| F-02 | 이벤트 수집 SDK            | P0       |
| F-03 | 방문자 세션 관리           | P0       |
| F-04 | 실시간 이벤트 동기화       | P0       |
| F-05 | 2D 마을 렌더링             | P0       |
| F-06 | 랜덤 방문자 캐릭터 생성    | P0       |
| F-07 | 페이지별 건물 및 공간      | P0       |
| F-08 | 캐릭터 이동 애니메이션     | P0       |
| F-09 | 건물별 활성 방문자 수      | P0       |
| F-10 | 방문자 이탈 처리           | P0       |
| F-11 | 방문자 및 페이지 정보 패널 | P1       |
| F-12 | 실시간 이벤트 피드         | P1       |
| F-13 | 커스텀 이벤트 효과         | P1       |
| F-14 | 데모 이벤트 시뮬레이터     | P0       |
| F-15 | 테마 및 배경 변경          | P2       |
| F-16 | 과거 이벤트 타임랩스       | P2       |
| F-17 | 공개 공유 링크             | P2       |

P0는 프로토타입 필수, P1은 초기 완성도를 높이는 기능, P2는 후속 확장 기능이다.

### F-01. 웹사이트 등록

**목적:** 이벤트를 수집할 웹사이트를 등록하고 식별한다.

**기능**

- 사이트 이름 등록
- 사이트 URL 입력
- 고유 `site_id` 생성
- 허용 도메인 설정
- 연동용 코드 제공
- 수집 상태 확인

**프로토타입 범위**

관리자 1명과 사이트 1개를 기본 지원한다. 다중 사용자 계정 및 결제 기능은 제외한다.

### F-02. 이벤트 수집 SDK

**목적:** 기존 웹사이트에 최소한의 코드로 이벤트 추적 기능을 제공한다.

**기본 자동 수집 이벤트**

| 이벤트          | 설명                            |
| --------------- | ------------------------------- |
| `session_start` | 새 방문 세션 생성               |
| `page_view`     | 페이지 최초 진입 또는 경로 변경 |
| `heartbeat`     | 활성 세션 유지                  |
| `page_leave`    | 페이지 이탈 시도 감지           |

**커스텀 이벤트 예시**

- `search`
- `product_click`
- `sign_up`
- `purchase`

커스텀 이벤트 이름은 사이트가 자유롭게 정한다(영문 소문자·밑줄 2~32자, 사이트당 50가지). 위 4종은 기본 표현이 있는 이름이고, 나머지는 대시보드 "이벤트 설정"에서 이름표·효과·소리·알림·매출 집계를 정한다.

**요구사항**

- 방문 세션 식별자를 생성한다.
- 동일 세션에서 페이지가 변경되어도 캐릭터 식별자를 유지한다.
- SPA 라우팅을 지원한다.
- 이벤트 전송 실패 시 웹사이트의 정상 동작에 영향을 주지 않는다.
- 기본적으로 입력값, 비밀번호, 사용자 개인정보는 수집하지 않는다.
- URL 쿼리 문자열과 해시를 기본적으로 수집하지 않는다.
- 고객 웹사이트의 기존 동의·추적 설정과 연동할 수 있어야 한다.

최초 프로토타입에서는 Next.js 기반 테스트 사이트를 우선 지원하며, 이후 범용 JavaScript SDK로 확장한다.

### F-03. 방문자 세션 관리

**목적:** 사이트 접속자를 각각의 가상 캐릭터와 매핑한다.

**기능**

- 세션별 고유 ID 발급
- 세션과 캐릭터 1:1 연결
- 현재 페이지 경로 관리
- 마지막 활동 시각 기록
- 활성 / 비활성 상태 판별

**초기 정책**

- Heartbeat 전송 주기: 15초
- 활성 세션 만료 기준: 마지막 활동으로부터 45초
- 동일 세션의 페이지 이동 시 기존 캐릭터 유지
- 새 방문 세션 생성 시 캐릭터 외형 랜덤 배정
- 탭 단위 세션을 사용하며 여러 탭은 각각 하나의 캐릭터로 간주

45초 기준은 초기 테스트값으로, 실제 이탈이 늦게 반영될 가능성이 있다.

### F-04. 실시간 이벤트 동기화

**목적:** 수집된 이벤트를 2D 마을 화면에 반영한다.

**지원 이벤트**

- 방문자 등장
- 방문자 이동
- 방문자 퇴장
- 사용자 행동 이벤트
- 건물별 인원 변화

**처리 원칙**

- 서버가 활성 세션 및 현재 페이지 상태의 기준이 된다.
- 클라이언트는 전달받은 상태를 바탕으로 애니메이션을 수행한다.
- 이벤트 중복 수신을 처리한다.
- 늦게 도착한 이벤트로 사용자의 페이지 상태가 역행하지 않도록 한다.
- 실시간 연결이 끊겼다가 복구되면 서버의 최신 상태로 재동기화한다.

### F-05. 2D 마을 렌더링

**목적:** 웹사이트를 하나의 작은 가상 세계로 표현한다.

**디자인 방향**

- 싸이월드 미니홈피 감성
- 2D 픽셀 아트 또는 SD 캐릭터 스타일
- 아이소메트릭에 가까운 쿼터뷰
- 파스텔 톤 색상
- 밝고 귀여운 동네 분위기
- 상시 움직이는 캐릭터와 소규모 환경 애니메이션

**기본 화면 요소**

- 마을 배경
- 도로 및 이동 경로
- 웹페이지를 상징하는 건물
- 방문자 캐릭터
- 건물별 방문자 수 표시
- 실시간 이벤트 알림
- 현재 접속자 수
- 페이지 정보 패널

**프로토타입 제약**

- 고정된 마을 레이아웃 사용
- 최대 8개 주요 페이지를 개별 건물로 표시
- 나머지 페이지는 '기타 페이지' 건물로 통합
- 자유로운 건물 배치 기능은 제외
- 최초 버전에서는 PC 화면을 우선 지원

### F-06. 랜덤 방문자 캐릭터

**목적:** 개별 세션을 시각적으로 구분한다.

**캐릭터 속성**

| 속성            | 초기 구현             |
| --------------- | --------------------- |
| 캐릭터 종류     | 6종                   |
| 색상            | 6종                   |
| 이동 방향       | 상하좌우              |
| 대기 애니메이션 | Idle                  |
| 이동 애니메이션 | Walk                  |
| 등장 효과       | Fade / Pop            |
| 퇴장 효과       | Fade / Walk Out       |
| 감정 표현       | 커스텀 이벤트 발생 시 |

캐릭터의 외형은 세션이 유지되는 동안 변경되지 않는다.

캐릭터를 클릭하면 익명 세션 정보와 현재 방문 페이지를 확인할 수 있다.

캐릭터의 그래픽 위치는 실제 웹사이트 좌표가 아니라 가상의 마을 좌표다.

### F-07. 페이지별 건물

**목적:** 웹사이트의 URL 경로를 공간 단위로 표현한다.

**기본 매핑 예시**

| URL 경로     | 건물 유형     |
| ------------ | ------------- |
| `/`          | 메인 광장     |
| `/products`  | 상점          |
| `/search`    | 도서관        |
| `/community` | 커뮤니티 센터 |
| `/mypage`    | 개인 주택     |
| `/checkout`  | 계산대        |
| `/other`     | 기타 건물     |

페이지별 건물 이름과 아이콘은 초기 설정 데이터로 관리한다.

미등록 URL은 지정된 기타 건물로 이동시킨다.

### F-08. 캐릭터 이동 애니메이션

**목적:** 방문자 페이지 전환을 캐릭터 이동으로 표현한다.

**동작 규칙**

1. 페이지 이동 이벤트 수신
2. 이전 건물과 다음 건물 확인
3. 이동 목적지 계산
4. 미리 지정된 길을 따라 캐릭터 이동
5. 목적지 도착 후 Idle 전환

**추가 규칙**

- 이동 속도는 화면 연출을 위해 일정 범위에서 조절한다.
- 같은 건물에 여러 캐릭터가 있을 경우 겹치지 않게 위치를 분산한다.
- 경로 변경 이벤트가 연속으로 발생하면 최신 목적지로 갱신한다.
- 건물당 수용 인원을 시각적으로 초과하면 일부 캐릭터를 주변에 분산 배치한다.

### F-09. 페이지별 밀집도 표현

**목적:** 방문자가 집중된 페이지를 한눈에 확인한다.

**시각적 표현**

| 활성 방문자 수 | 표현                |
| -------------- | ------------------- |
| 0명            | 일반 건물           |
| 1~4명          | 일반 캐릭터 표시    |
| 5~9명          | 건물 주변 활동 증가 |
| 10명 이상      | 건물 위 강조 효과   |

위 수치는 프로토타입용 임시값으로 사이트 트래픽 규모에 따라 조정한다.

건물 방문자 수는 실제 활성 세션 집계값을 표시하고, 애니메이션은 별개로 처리한다.

### F-10. 방문자 이탈 처리

**목적:** 비활성 방문자가 화면에 계속 남지 않도록 한다.

**동작**

- 명시적인 이탈 신호 수신
- Heartbeat 만료 확인
- 활성 세션 제거
- 캐릭터 퇴장 애니메이션
- 건물 인원 감소

네트워크 연결 일시 중단 등으로 오차가 발생할 수 있으므로, 접속자 수는 추정 활성 세션 기준으로 표기한다.

### F-11. 방문자 및 페이지 정보 패널

**캐릭터 선택 시**

- 익명 세션 ID 일부
- 현재 페이지
- 접속 후 경과 시간
- 최근 이벤트
- 현재 상태

**건물 선택 시**

- 페이지 이름
- URL 경로
- 현재 활성 방문자 수
- 최근 이벤트 발생 건수

특정 개인을 식별할 수 있는 사용자 이름·이메일 등은 표시하지 않는다.

### F-12. 실시간 이벤트 피드

화면 우측 또는 하단에 최신 이벤트를 기록한다.

**예시**

- 14:21:03 — 방문자 #A32가 입장했어요.
- 14:21:08 — 방문자 #A32가 상점으로 이동했어요.
- 14:21:12 — 방문자 #B18이 상품을 클릭했어요.
- 14:21:16 — 방문자 #C41이 검색했어요.
- 14:21:25 — 방문자 #B18이 떠났어요.

**기능**

- 최신순 정렬
- 최대 30개 이벤트 표시
- 자동 갱신
- 이벤트 유형별 아이콘 표시
- 이벤트 선택 시 해당 캐릭터 강조

### F-13. 커스텀 이벤트 효과

**초기 지원 이펙트**

| 이벤트          | 효과                |
| --------------- | ------------------- |
| `search`        | 돋보기 말풍선       |
| `product_click` | 별 반짝임           |
| `sign_up`       | 환영 폭죽           |
| `purchase`      | 동전 및 축하 이펙트 |

이벤트는 세션 ID를 기준으로 해당 캐릭터에 연결한다.

별도의 캐릭터가 없는 경우 이벤트 피드에만 기록한다.

### F-14. 데모 이벤트 시뮬레이터

**목적:** 실제 방문자가 적더라도 시연 및 테스트를 수행할 수 있도록 한다.

**기능**

- 시뮬레이션 시작 / 중지
- 가상 방문자 추가
- 무작위 페이지 이동
- 이벤트 강제 발생
- 가상 방문자 이탈
- 모든 가상 방문자 제거
- 시뮬레이션 방문자 수 설정

실제 사용자와 가상 사용자를 반드시 구분하며, 데모 이벤트는 실제 방문 통계에 포함하지 않는다.

## 5. 기술 아키텍처

### 5.1 권장 기술 스택

| 영역        | 기술                               |
| ----------- | ---------------------------------- |
| 프론트엔드  | Next.js / React / TypeScript       |
| 2D 렌더링   | PixiJS                             |
| UI          | Tailwind CSS / shadcn/ui           |
| 이벤트 수집 | 경량 JavaScript SDK                |
| API         | Next.js Route Handler 또는 Node.js |
| DB          | PostgreSQL / Supabase              |
| 실시간 통신 | SSE 또는 WebSocket                 |
| 상태 관리   | Zustand                            |
| 배포        | Vercel + 별도 실시간 서버(필요 시) |

**초기 설계 원칙**

실시간 이벤트가 여러 관리자 클라이언트에 전달될 수 있도록 이벤트 수집, 세션 상태 관리, 렌더링 영역을 분리한다.

서버리스 환경의 지속 연결 제한을 고려해 SSE/WebSocket의 운영 환경을 별도로 검토한다.

### 5.2 이벤트 처리 흐름

```text
고객 웹사이트
    │
    ▼
Tracking SDK
    │ page_view / heartbeat / custom event
    ▼
Event Collector API
    │
    ├── 이벤트 검증 및 정규화
    │
    ▼
Session Manager
    │
    ├── 방문자 상태 업데이트
    ├── 페이지별 인원 집계
    │
    ▼
Realtime Publisher
    │
    ▼
Visitown Dashboard
    │
    ├── 방문자 등장
    ├── 캐릭터 이동
    ├── 이펙트 실행
    └── 이벤트 피드 업데이트
```

### 5.3 SDK 이벤트 형식

```json
{
  "event_id": "evt_123",
  "site_id": "site_demo",
  "session_id": "sess_abc123",
  "event_type": "page_view",
  "page_path": "/products",
  "timestamp": "2026-10-22T09:30:00Z",
  "properties": {}
}
```

**필수 필드**

- `event_id`: 이벤트 중복 수신 방지
- `site_id`: 사이트 식별
- `session_id`: 익명 세션 식별
- `event_type`: 이벤트 종류
- `page_path`: 현재 페이지 경로
- `timestamp`: 이벤트 발생 시각
- `properties`: 허용된 커스텀 속성

커스텀 이벤트의 속성은 개인정보가 포함되지 않도록 허용 목록 기반으로 필터링한다.

**SDK 설치 옵션(`<script>` 속성)**: `data-consent="wait"`(동의 뒤 `visitown.consent(true)`), `data-widget="1"`(방문자용 미니 위젯, 대시보드에서 켠 사이트만 뜬다), `data-errors="1"`(JS 오류를 `js_error` 이벤트로, 메시지는 마스킹·120자). 들어온 주소의 `utm_source`·`utm_medium`·`utm_campaign`은 `session_start` 속성으로 같이 보내고, 유료 매체면 `referrer`를 `ad`로 둔다.

### 5.4 기본 API

| Method | Endpoint                | 역할                    |
| ------ | ----------------------- | ----------------------- |
| POST   | `/api/events`           | 이벤트 수집             |
| GET    | `/api/sites/:id/state`  | 활성 세션 스냅샷        |
| POST   | `/api/sites/:id/stream-ticket` | SSE용 30초 일회용 티켓(Bearer 헤더). 응답 `{ ticket, expiresIn }` |
| GET    | `/api/sites/:id/stream?ticket=…` | 실시간 상태 변경 구독. `?ticket=`(대시보드) 또는 `?embed=`(공개), `?token=`은 401 |
| GET    | `/api/sites/:id/pages`  | 페이지 매핑 정보        |
| GET    | `/api/sites/:id/badge?embed=키` | "지금 N명 보는 중" SVG 배지(`&format=json`이면 숫자) |
| POST   | `/api/sites/:id/notes`  | 리플레이 메모(`note` 이벤트) |
| GET/PUT/POST | `/api/sites/:id/webhook` | 슬랙·디스코드 웹훅 설정·시험 전송 |
| GET/PUT | `/api/sites/:id/widget` | 미니 위젯 정보(공개)·켬/끔 |
| POST   | `/api/dev/simulate`     | 개발용 가상 이벤트 생성 |

`/api/dev/simulate`는 개발 환경에서만 허용한다.

실시간 스트림과 사이트별 상태 조회 API는 관리자 인증을 요구한다. 이벤트 수집 API는 공개 사이트 키, 허용 Origin, Rate Limit, 요청 검증 등으로 오남용을 완화한다.

## 6. 프로토타입 개발 범위

### Phase 1 — 시각화 데모

**목표:** 실제 이벤트 연동 없이 가상 데이터로 UX를 검증한다.

- 고정된 2D 마을 구현
- 페이지 건물 4~6개 구현
- 랜덤 캐릭터 생성
- 건물 간 이동
- 캐릭터 등장 / 퇴장
- 건물별 방문자 카운트
- 데모 이벤트 시뮬레이터

**완료 기준:** 가상 방문자 10~30명이 동시에 이동하며, 건물별 인원 변화가 자연스럽게 보일 것.

### Phase 2 — 실시간 데이터 연동

**목표:** 실제 웹사이트 방문 이벤트를 화면에 반영한다.

- 이벤트 수집 API
- Next.js용 Tracking SDK
- 세션 생성 및 유지
- 페이지 이동 추적
- Heartbeat 및 세션 만료
- 실시간 이벤트 전송
- 초기 상태 스냅샷 / 재연결

**완료 기준:** 별도의 테스트 웹사이트에서 페이지를 이동하면 해당 캐릭터가 대시보드에서 올바른 건물로 이동할 것.

### Phase 3 — 인터랙션 완성

**목표:** 단순한 시연에서 실제 사용 가능한 수준으로 개선한다.

- 캐릭터 선택 패널
- 건물 정보 패널
- 실시간 이벤트 피드
- 커스텀 이벤트 이펙트
- 확대 / 축소
- 연결 상태 표시
- 기본적인 성능 최적화

**완료 기준:** 테스트 사용자가 별도 설명 없이 웹사이트 방문·이동·이벤트 발생 상황을 이해할 것.

## 7. 비기능 요구사항

### 7.1 성능

초기 검증 목표는 다음과 같다.

- 일반적인 PC 환경에서 60FPS를 목표로 렌더링
- 캐릭터 100개 동시 표시 성능 검증
- 이벤트 수신부터 화면 상태 반영까지 정상 네트워크 환경에서 1초 이내 목표
- 보이지 않는 캐릭터의 불필요한 렌더링 최소화
- 이동 애니메이션은 프레임 단위로 처리하되 네트워크 이벤트마다 전체 캔버스를 재생성하지 않음

위 수치는 측정된 성능이 아니라 검증을 위한 목표값이다.

### 7.2 개인정보 및 보안

- 기본적으로 익명 세션 기반 추적
- IP 주소 및 개인정보의 불필요한 영속 저장 방지
- URL 쿼리 파라미터와 입력 데이터 기본 제외
- 수집 가능한 이벤트 속성 제한
- 고객 사이트의 추적 동의 상태 반영 지원
- 서비스별 접근 권한 분리
- 이벤트 전송량 제한
- 데이터 보관 및 만료 정책 적용
- 개인정보처리방침·이용약관(데이터 처리 조항 포함)은 `legal/`에 한국어·영어로 둔다. GDPR·UK GDPR·CCPA/CPRA·개인정보보호법 기준으로 작성했고, 운영자 정보 빈칸을 채운 뒤 출시 전 법률 검토를 받는다

### 7.3 안정성

- 이벤트 수집 실패가 고객 웹사이트에 영향을 주지 않을 것
- 네트워크 단절 시 관리자 대시보드 자동 재연결
- 중복 이벤트로 캐릭터가 중복 생성되지 않을 것
- 서버 재시작 후 활성 세션을 재구성하거나 안전하게 초기화할 것

- 동시 캐릭터 100개 기준 렌더링 성능 확인

### 사용자 경험 성공

- 첫 화면에서 서비스의 목적을 쉽게 이해할 수 있음
- 방문자의 유입과 페이지 이동이 직관적으로 보임
- 캐릭터와 공간의 시각적 완성도가 충분한 흥미를 제공
- 일반적인 분석 대시보드와 다른 재미를 체감할 수 있음

### 사업적 검증

프로토타입을 10~20명의 개인 개발자 및 서비스 운영자에게 시연한다.

다음 항목을 확인한다.

1. 실제 본인 사이트에 설치하고 싶은가?
2. 설치 후 반복적으로 확인할 의향이 있는가?
3. 어떤 이벤트를 캐릭터로 표현하고 싶은가?
4. 기존 분석 도구 대신 사용하는가, 함께 사용하는가?
5. 유료 기능에 대한 지불 의향이 있는가?

핵심 성공 지표는 조회수보다 **실제 사이트 연동 비율과 재방문율**로 설정한다.

## 12. 최종 구현 방향

**프로토타입의 최우선 목표는 분석 기능의 완성도가 아니라 '살아 있는 웹사이트를 바라보는 재미'를 검증하는 것이다.**

따라서 개발 우선순위는 다음과 같다.

1. 귀엽고 완성도 높은 2D 마을
2. 방문자와 캐릭터의 안정적인 매핑
3. 직관적인 페이지 이동 애니메이션
4. 실시간 방문자 밀집도 표현
5. 기본 이벤트 연동
6. 사용자 정보 패널과 부가 분석 기능

**최종 산출물**

- 실제 작동하는 Visitown 대시보드
- 샘플 Next.js 웹사이트
- 연동용 Tracking SDK
- 가상 이벤트 시뮬레이터
- 기본 건물·캐릭터 에셋
- 프로토타입 설치 및 실행 가이드

이 프로토타입을 기반으로 향후 개발자용 SaaS 제품으로의 확장 여부를 결정한다.
